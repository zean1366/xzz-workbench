# 喜姿姿工作台 · 腾讯云 SCF 云函数部署指引

> 目标：手机端独立读写飞书多维表格，电脑不需要一直开机。
> 后端：腾讯云 SCF 云函数（国内服务器，访问稳定）。
> 前端：GitHub Pages（不变）。
> 数据源：飞书多维表格（唯一数据源，token 不暴露到前端）。

---

## 整体架构

```
手机 / 电脑（GitHub Pages 前端 HTML）
        ↓ fetch 跨域 HTTPS
腾讯云 SCF 云函数（index.js）
  · 用 refresh_token 刷新 access_token（内存缓存）
  · 调飞书多维表格 API 读写 8 个模块
  · 飞书 refresh_token 存环境变量，不暴露到前端
        ↓
飞书开放平台 API（open.feishu.cn）
        ↓
飞书多维表格（个人云文档，永久存储）
```

手机端独立保存新增记录 = 手机直接调腾讯云 SCF → SCF 调飞书 → 数据写入飞书表。
电脑只要不开机就不参与同步；电脑开机后打开工作台，会自动从飞书拉取最新数据。

## 第 6 步：创建 API 网关触发器（拿到 SCF URL）

1. 进入 `xizizi-workbench` 函数 → 左侧「**触发管理**」（或顶部「触发器」标签页）
2. 点「**创建触发器**」
3. 触发方式选：**API 网关触发器**
4. API 网关服务：选「**新建服务**」，服务名填 `xizizi-workbench-gw`
5. 路径填：`/`
6. 请求方法选：**ANY**（同时支持 GET / POST / OPTIONS）
7. 鉴权类型选：**免鉴权**（前端跨域访问不用签名，最简单）
8. 集成类型选：**集成代理**（让 SCF 函数处理整个 HTTP 请求和响应）
9. 点「**保存**」
10. 创建完成后会显示一个 URL，类似：
    ```
    https://service-xxxxxxxx-xxxxxxxx.gz.tencentcloudapi.com/release/
    ```
11. **复制这个 URL**（去掉末尾的斜杠 `/`），下一步要用：
    ```
    https://service-xxxxxxxx-xxxxxxxx.gz.tencentcloudapi.com/release
    ```

## 第 10 步：在飞书新建「习惯打卡」多维表格（checkin 模块）

> 目标：checkin 模块可以跨设备查看月度打卡，和 todo/money 一样同步飞书。

1. 打开飞书 → 「云文档」→ 「新建」→ 「多维表格」
2. 命名：**习惯打卡**
3. 默认会有一张表（数据表 1），把它改名为：**打卡记录**
4. 字段设置（共 3 个字段）：
   - 字段1：名称 `习惯名称`，类型 `文本`
   - 字段2：名称 `打卡记录`，类型 `多行文本`（**重要：不是复选框，也不是日期，是多行文本**，因为要存 JSON 字符串）
   - 字段3：名称 `自动关联模块`，类型 `单选`，添加选项：
     - `todo`、`weeklylearn`、`content`、`quickshop`、`money`、`period`、`diary`、`checkin`
5. 在表里手动录入 3 条种子记录（对应前端默认的 3 个习惯）：
   - 习惯名称：`记日记`，自动关联模块：`diary`
   - 习惯名称：`门店记录`，自动关联模块：`quickshop`
   - 习惯名称：`生活收支`，自动关联模块：`money`
   - 「打卡记录」字段先留空，前端会自动写入
6. 从浏览器地址栏复制该表 URL，格式如下：
   ```
   https://xxx.feishu.cn/base/【baseToken】?table=【tableId】
   ```
   - `baseToken` 是 `/base/` 后面那段字符
   - `tableId` 是 `?table=` 后面那段以 `tbl` 开头的字符
7. 回到腾讯云 SCF 控制台 → 函数配置 → 环境变量 → 编辑 `FEISHU_TABLE_CONFIG`
8. 把 JSON 里的 `"checkin":{"baseToken":"新建后填这里","tableId":"新建后填这里"}` 替换成你的真实 token：
   ```json
   "checkin":{"baseToken":"你的baseToken","tableId":"你的tableId"}
   ```
9. 保存

## 30 天一次的刷新流程（后续维护）

腾讯云 SCF 实例闲置会被销毁，冷启动时用环境变量里的 refresh_token 重新刷新 access_token。飞书 refresh_token 30 天有效，到期后：

1. 电脑重复第 8 步：启动本地 server.js → 访问 http://localhost:8080/api/auth/login → 授权 → 拿新 refresh_token
2. 把新的 refresh_token 填回腾讯云环境变量 `FEISHU_REFRESH_TOKEN`
3. 不需要重新部署代码，只改环境变量即可立即生效

> 提示：飞书 refresh_token 每次刷新会返回新 token，但旧 token 在 30 天内仍然可用。
> 因此 30 天内即使 SCF 实例销毁多次，仍能正常工作。
> 30 天到期前刷新一次即可。

## 故障自查清单

| 现象 | 排查方向 |
|------|---------|
| 前端 fetch 报 CORS 错误 | API 网关触发器没建 / 鉴权类型选错（应为免鉴权） |
| 前端报 401 / "未授权" | refresh_token 没填 / 已过期 30 天，重做第 8 步 |
| 前端报 500 | SCF 函数内部错误，去控制台「日志查询」看堆栈 |
| 飞书返回 Forbidden | 飞书应用没开通 bitable:app 权限 / 没把应用加为多维表格协作成员（参考 sync-config.js 注释） |
| 数据没同步过来 | 浏览器 F12 看 Network → 找 `?action=pull` 请求 → 看响应 |
| 推送失败本地缓存了 | localStorage 里 `xizizi-pending-sync-v1` 有数据，下次 syncAll 会自动重推 |
| GitHub Pages 没更新 | 等 1 分钟，或在 GitHub 仓库 Actions 标签页看部署状态 |

## 关键约束（确认）

- 飞书多维表格为唯一数据源，飞书 refresh_token 只存腾讯云环境变量，不暴露到前端
- 前端不读不写任何飞书密钥，所有调用都经腾讯云 SCF 中转
- 本地 server.js 保留作为「授权入口」和「应急 fallback」（app-config.js 的 USE_LOCAL_FALLBACK 开关）
- 碎片灵感杂事（diary）模块保持纯本地，不同步飞书
- 习惯打卡（checkin）模块同步飞书，跨设备查看月度打卡，不清理旧数据
- 图片上传相关功能延后开发，本次不做
- 后续重构底层架构必须先和用户确认，禁止擅自修改存储逻辑
